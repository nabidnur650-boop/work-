# Security policy

## Supported release

Technical artifact v1.0.0 is the supported release. Historical
snapshots are retained for provenance but are not maintained.

## Reporting a vulnerability

Do not open a public issue for a suspected credential leak, unsafe archive,
path disclosure, dependency compromise, or code-execution vulnerability.
Use GitHub's private vulnerability-reporting flow from the repository's
**Security** tab when enabled. If that channel is unavailable, contact the
accountable maintainer through a private channel listed in the final
repository or paper metadata.

No email address is fabricated in this artifact. Do not include provider
audio, personal data, access tokens, or proprietary model files in a report.

The maintainers should acknowledge a complete report within seven days,
confirm scope privately, and coordinate disclosure after a fix is available.
Scientific disagreements and reproduction questions belong in the issue
tracker, not the security channel.
